# Status simplification implementation plan

Objective: ship-ready replacement of public feature certification with objective request telemetry, independent operator notices and honest historical measurement windows. No application business changes. Implementation used an isolated Git worktree; the existing dirty checkout was left untouched.

Final owner direction: preserve the canonical public wordmark/icons and the supplied
up/degraded status mockups. Page order is overall hero, compact operator/observation
banner and support email, simple teacher/student question cards, then platform
connectivity and numerical request measurements/history. Teacher labels are Yes,
Probably not, Possibly down and Not recently verified using SPEC-OPS-006's
versioned request-proxy mapping. The hero also considers global application
requests and active operator notices. Internal integrity proof remains separate.

An independent collector read of the existing /health/status endpoint preserves
actual endpoint/database connectivity only, discarding feature placeholders.
It persists platform-check-v1 via append_platform/current_platform,
platform_observations (seven-day TTL) and platform_current/current; this does not
feed request-history denominators. No new application endpoint or business change.

Phase 0 discovery complete: status/telemetry.py translation is dormant; collector consumes health/status placeholders; public projection merges notices and automated claims; Firestore existing notice store is reusable. Grafana is operator-authenticated. Existing host loopback Loki is the metric source and reviewed route expressions are maintained in `status_service/route_groups.json`. No public access to raw Loki/Grafana is permitted.

Phase 1 authority: amend DOM-OPS-001 public feature facets to observed request health; preserve internal scoped verifiers and audit obligations. Preserve SPEC-OPS-005 as the internal integrity evaluator contract and introduce SPEC-OPS-006 for public numerical measurements. Amend SPEC-OPS-002 and SOP-OPS-001 to distinguish request snapshots, history, and operator interpretation, with optional source snapshot links for human observations. SPEC-OPS-003 HTTP code does not classify FEAT/business outcomes; permit explicitly named HTTP response distribution evidence separately. Bump versions/index and record supersession of old public requirements. No compatibility bridges.

Phase 2 implementation interfaces:
- status/measurements.py pure strict closed contract: components service,login,attendance,payroll,roster,classroom_economy. Schema version request-telemetry-v1. Snapshot dictionary: schema_version, sampled_at (UTC ISO), window_seconds=300, source_latest_at (UTC ISO or null), components list. Each component: key, request_count (nonnegative int or null), http_1xx_count,http_2xx_count,http_3xx_count,http_4xx_count,http_404_count,http_500_count,http_5xx_count (same), p80_ms,p95_ms finite nonnegative or null, collection_state OK/UNAVAILABLE. Counts partition total; 404 subset4xx 500 subset5xx; zero requests means quantiles null. On unavailable all values null. Source freshness max180sec; snapshot max300sec; no invented zero on failed query; reject unknown fields/keys/bools/nonfinite/unbounded numbers. Constants thresholds server error percent>2,404 percent>5,p95_ms>1500,minimum 20 requests. Any threshold crossing can surface without minimum; NORMAL needs minimum20, otherwise LOW_TRAFFIC. Distinct NO_TRAFFIC,MONITOR_UNAVAILABLE,STALE; deterministic classification no domain truth. Closed route mappings from the reviewed checked-in registry, including service global upstream. Unknown/malformed source fail closed. Sample time generated at source not receipt. snapshot_id deterministic sampled UTC minute; collector once/min; counts errors percentages computed from counts.
- status_service/log_sampler.py reads local Loki only, fixed queries per component grouped to empty labels; no raw query input. Query exact shared UTC evaluation time, counts by status-class plus404/500, quantiles by(). Latest nginx log timestamp query locally, discard raw values. Output validated bounded JSON atomically to /var/lib/cth-status/telemetry.json using systemd oneshot/minute timer. No app DB/identities. New nginx exact /health/telemetry serves static JSON with Cache-Control no-store, only GET/HEAD and normal existing Cloudflare Access/origin restrictions; no changes to Grafana auth. Provisioning documented/scripted; no automatic remote installation during implementation.
- status_service/collector.py replaces old feature-placeholder health/status collection with fixed health/telemetry URL and existing CF service-token transport (no redirect, timeout,size limit). Validate snapshot, store append_snapshot(snapshot, received_at=now); transport failures record a separate collector failure with receipt time, never fabricating source time or blocking a valid same-minute source snapshot. Preserve failed source time and no freshness laundering. Persist safe closed data only; log only bounded outcomes.
- store APIs: append_snapshot(snapshot_or_none,received_at,diagnostic=None), current_snapshot(), measurement_history(days=90). Single snapshot per minute transactional/idempotent, append-only telemetry_snapshots; telemetry_current/current pointer monotonic; telemetry_days/YYYY-MM-DD per component counters sampled, measured,normal, elevated_errors,high_latency,other. Atomically update only once; day by source time; reject stale snapshot at collector. All reads before writes. Daily history known 90 UTC dates, no data explicitly gaps; observed windows normal/measured percentage, coverage against elapsed scheduled minutes, not business uptime. Keep existing operator notice records and resolution APIs; remove unused old public observation writer/reader, no migration of old observations into new measurement history. Old evidence remains retained.
- UI: follow the supplied mockups and original public shell: overall hero, banner/support email, compact teacher question cards, then independently measured platform connectivity and request/history details. Display counts, 404/500/5xx %,p80/p95, timestamps and measured state labels only in the lower platform area; 4xx distribution contextual, not generic system failure. State thresholds clearly disclosed with accessible text details. Empty/stale monitoring never reassuring green. History bars accessible keyboard/touch, text status and percentages/coverage; no hover-only information. Keep independent status branding/css and secure operator auth/CSRF. Operator notices can publish own investigation reference without requiring fabricated observation IDs; existing links retained when provided. Recovery timestamp parse/validation must remain truthful. GET performs only persisted reads; never query Loki from browser.
- Existing internal status/projection.py evidence classes may remain only if internal consumers exist; remove obsolete public card APIs/tests rather than compatibility paths. Update focused test lists to new status tests; internal tests retained as applicable. Deployment same Cloud Run collector job identity/scheduler, same credentials. Document rollout prerequisites and fail-closed transport verification. No app release required.

Phase 3 verify: focused tests only after checking pytest_result. Contract malformed/unknown/PII labels, source lag, collection failures, zero traffic, low traffic,404 vs5xx, quantiles, window bounds, duplicate/out-of-order writes, day rollover, history gaps/coverage, notice independence, auth/CSRF, safe GET. Sampler mocked Loki multi-series rejection + real read-only local queries where feasible. Render local UI populated/idle/stale with browser. Compile/diff check. No full suite. Review privacy/authority/no stale compatibility code. Fix verified findings before commit.

Phase 4 delivery: commit verified isolated branch, draft PR using /.github template, attach PR. Production deployment remains gated on merging through configured workflow and installing reviewed monitoring sampler/nginx config. Do not claim shipped before live snapshot -> collector -> Firestore -> rendered card evidence. No merge without explicit user instruction.
