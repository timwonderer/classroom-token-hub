### Why this release

- **Purchased hall passes can be reversed (#1530).** Owner ruling 2026-10-08: reversing a purchase invalidates
  every entitlement it paid for, hall passes included (`SPEC-OPS-001` §3.3). v2.2.0 excluded `HALL_PASS`, so rows
  1275 and 1277 in class `1da9085a` (1 and 1,000 passes, bought on 2026-10-08 without the money; see the v2.2.0
  record) could not be reversed.
- **Hall-pass use is the log only (#1530).** Owner ruling 2026-10-09: the hall-pass log is the only legal
  consumption record. Approval no longer writes a Store `CONSUMED` event; one rule (a terminal event, or a log
  naming the pass) decides whether a pass is spent, and every reader uses it.
- **Reservation and serialization (#1530).** A pass with a request waiting is reserved for it: nothing ends it
  until the request is approved or rejected, and an item with a request waiting can't be reversed, for every
  item type. Every writer that can end a hall pass takes the holder's seat lock before it reads whether the
  pass is spent.

## Rollback

- **Prefer fixing forward.** Rolling the code back to v2.2.0 (`5ebae62db`) is not clean once any pass has been
  used under v2.2.1: such a pass has a log but no `CONSUMED` event, so v2.2.0 counts it as unused, offers it
  again, and its next approval for that pass collides with `uq_hall_pass_logs_hall_pass_id` and fails. Before a
  code rollback, count logs whose pass has no terminal event; if there are any, fix forward instead.
- **Fix forward:** a reviewed code fix on `main`, released the same way.
- **Restore:** only if data were damaged. Stop the application and restore `cth-db-20261010T202331Z-manual`.
