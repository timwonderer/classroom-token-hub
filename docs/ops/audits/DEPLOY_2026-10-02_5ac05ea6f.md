## Release run

**The application was stopped first.** Before dispatching the workflow, the operator ran `systemctl stop` on the
application unit and confirmed it was `inactive`. The reasons:

- `release-v2.yml` runs `flask db upgrade` while the old application is still serving.
- The database role has `lock_timeout=10s` (an OPS-DB-001 corrective action), so a migration that waits behind
  application locks fails.
- #1450's contract migration cannot run under the old code.

Stopping the application removed the lock contention.

**The workflow.** Run [36966092454](https://github.com/timwonderer/classroom-token-hub/actions/runs/36966092454),
revision `5ac05ea6f`, lineage `main`. Every step succeeded, including "Production health passed".

Migrations applied, in order:

`f4b8d2a6c1e9` → `bb5557cb1609` (#1461) → `a7e3c9d1f5b2` (#1450) → `dd52b19d48d8` (#1452) → `624c6b7223df` (#1452) →
`a4b50fee84c3` (#1463)

Notable migration output:

- `payroll_event.policy_uuid` remapped on 448 rows.
- Foreign keys `attendance_sessions_actor_seat_id_fkey` and `payroll_event_actor_seat_id_fkey` recreated
  `ON DELETE CASCADE`.
- Triggers `payroll_settings_no_update`, `payroll_settings_no_delete`, `payroll_event_no_update` and

## Worker count

- On 2026-10-02 at 02:21:06 UTC, before this release, production was reverted from 2 workers to 1. Pending hall-pass
  requests lived in per-process memory, so teachers got "Pending request not found" on about half of their
  approvals.
- #1462, in this release, moves pending requests into `pending_actions`.
- Under SOP-DEP-001 v2.6, two workers may be restored only after hall passes are verified on this release. That is a
  separate operations step and has not been done. Production runs one worker.
