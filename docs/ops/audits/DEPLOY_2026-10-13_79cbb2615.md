### Why this release

- **PROD-PAY-001 correction over-reporting (#1559).** F5 (#1536, in v2.2.3) made `record_payroll_event` return the
  existing event on an idempotency-key replay instead of raising, so the correction route counted a student
  already corrected by a concurrent approval as paid again. No second credit was ever written; only the
  reported list was wrong. `PayrollEventResult.replayed` now carries the outcome and the route skips replays. The
  correction screen is open until 2026-10-31.
- **Werkzeug 3.1.9 and Mako 1.4.2 (#1564; Dependabot alerts #93, #92, both medium).** Both advisories are
  Windows-only; production (Ubuntu) was not exposed. Mako is used only by Alembic to render new migration files.
