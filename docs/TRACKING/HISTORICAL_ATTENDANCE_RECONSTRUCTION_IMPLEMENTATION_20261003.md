## Evidence and immutability boundary

Ledger returns immutable `ReconstructedSettlement` / `ReconstructedOrigin` evidence from internally validated domain inputs. These are separate from `LedgerCreationEvidence` and Operations `VerifiedCreationEvidence`; no caller boolean, copied signature or guessed creation value supplies either type. Reconstruction does not declare an original protected row lawful or VERIFIED. `ReconstructedSettlement(graph, origins, material, creation_evidence=())` preserves the complete modern creation-proof set for recovery revalidation, including a graph with no monetary origins; this never creates a fictional zero Ledger credit or upgrades old lineage.

Original NULL linkage remains UNVERIFIED. Retired v1 payload coverage that cannot be faithfully reconstructed remains DEGRADED/VERIFIER_COVERAGE_UNAVAILABLE; where an original link exists, its actual complete envelope/chain must authenticate. A known payload/HMAC/chain/scope contradiction remains INVALID and denies. Modern v2/v3 originals and modern recovery/business effects retain complete exact creation proof; a malformed modern record cannot fall through to historical reconstruction.

Only the new correction decisions and effects acquire current lawful lineage. No original attendance, payroll, policy, signature, posting sequence, reservation or compensation field is mutated or backfilled. No persisted earnings cache, proof enrollment, replacement historical signature, guessed PENDING value, status enumeration or digest search is introduced. Original cycles and completed Interpretation remain unchanged.
